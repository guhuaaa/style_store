# Bauhaus — UI Translation

## Structure
以 `functional geometry` 和 `asymmetric grid` 改造布局、网格、对齐和层级；禁止在固定 SaaS 卡片模板上仅改变皮肤。

## Components
面板、卡片、分割线、导航和图表应复用同一形状与节奏规则；关键数据仍须可扫描、可对比。

## Typography / Color
文字层级和色彩关系必须支持信息结构。历史色彩逻辑被转换为数字界面中的强调、状态和分区，而不是复刻旧作配色。

## Ornament / Image / Motion
装饰只锚定边框、分区、插图或导航节点；图像与动效必须强化 `shape-based information hierarchy`，不可遮蔽数据。

## Intensity
- **LOW**：保持成熟产品框架，仅引入少量 CORE DNA。
- **MEDIUM**：布局、形状、字级和色彩关系明显受影响。
- **HIGH**：允许强构图与强图形语言，但保留导航、筛选、KPI、图表、列表、表格和状态。

## Do
- 使用 Style DNA 作为生成和评审依据。
- 对同一 Benchmark 内容实施结构变化。

## Avoid
- 只换色、纹理或装饰；此类结果标记为 `SURFACE_MIMICRY`。
- 使用历史作品中的人物或题材取代形式语言。
